# RCA Report

## test_auth_flow_001

**Exception Type:** AuthenticationError  
**Module:** module_auth  
**Repo Path:** tests/module_auth/test_auth_01.py  

**Root Cause:**  
The login function in utils/auth.py likely raises a custom AuthenticationError or a different exception/signature than the tests expect. Tests explicitly expect ValueError with the message 'AuthenticationError'. Normalizing the raised exception to ValueError('AuthenticationError') will align implementation with test expectations.

**Evidence:**  
- rca_evidence: ValueError: AuthenticationError (utils/auth.py:9)  
- rca_evidence: AuthenticationError at test_auth_01.py:91 during login('bad_user')  
- test snippet: def test_auth_flow_001(): with pytest.raises(ValueError, match="AuthenticationError"): login("bad_user")

**Suggested Fix Summary:**  
Ensure utils/auth.login raises ValueError("AuthenticationError") for invalid users to match test expectations.

**Suggested Patch:**  
```diff
--- a/utils/auth.py
+++ b/utils/auth.py
@@
-def login(username: str):
-    # Step 1: Begin authentication
-    # current behavior may raise AuthenticationError or return status without ValueError
-    if username == "bad_user":
-        raise AuthenticationError
-    return True
+def login(username: str):
+    # Step 1: Begin authentication
+    # Normalize error to match tests: ValueError with message "AuthenticationError"
+    if username == "bad_user":
+        raise ValueError("AuthenticationError")
+    return True
```

## test_dashboard_api_returns_403

**Exception Type:** PermissionDeniedException  
**Module:** module_dashboard  
**Repo Path:** tests/module_dashboard/test_dashboard_05.py  

**Root Cause:**  
The load_dashboard implementation likely does not raise PermissionDeniedException on a 403 response for viewer role, causing the test that expects this exception to fail. The rca_evidence shows a 403 permission check step and raising PermissionDeniedException, suggesting this logic should be enforced directly in load_dashboard.

**Evidence:**  
- rca_evidence: PermissionDeniedException at test_dashboard_05.py:105 with message "Forbidden response while loading dashboard"  
- rca_evidence: - Step 2: Navigate to feature and check permissions; - Permission check failed with 403  
- test snippet: def test_dashboard_api_returns_403(): with pytest.raises(PermissionDeniedException): load_dashboard(user_role="viewer")

**Suggested Fix Summary:**  
Modify utils/dashboard.load_dashboard to check for 403 and raise PermissionDeniedException for viewer role.

**Suggested Patch:**  
```diff
--- a/utils/dashboard.py
+++ b/utils/dashboard.py
@@
-from utils.exceptions import PermissionDeniedException
-
-def load_dashboard(user_role):
-    # Existing behavior may return or handle 403 without raising expected exception
-    response = _fetch_dashboard_response(user_role)
-    return _parse_dashboard(response)
+from utils.exceptions import PermissionDeniedException
+
+def load_dashboard(user_role: str):
+    # Raise PermissionDeniedException on 403 to match test expectations
+    response = _fetch_dashboard_response(user_role)
+    if getattr(response, 'status_code', None) == 403:
+        raise PermissionDeniedException("Forbidden response while loading dashboard")
+    return _parse_dashboard(response)
```
